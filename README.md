# etl-cafe

End-to-end data pipeline: a **dirty** cafe sales dataset is cleaned, loaded into a
normalized **MariaDB** database, served by a read-only **REST API**, and visualized
in a **Power BI** dashboard. The API is implemented in **three languages**
(Python, Node.js and Go) that are proven to return identical responses.

```
dirty_cafe_sales.csv ──► limpieza.py ──► cafe_sales_clean.csv ──► carga.py ──► MariaDB ◄── API ──► Power BI
   (raw, with errors)      (clean)          (+ cleaning report)     (load)     (normalized)  (JSON)   (dashboard)
                                                                                              ├─ Python (FastAPI) :8000
                                                                                              ├─ Node (Express)   :3000
                                                                                              └─ Go (net/http)    :8080
```

**Validated end to end:** the Power BI KPI cards match `/summary` and the clean CSV
exactly: **80,041.50** revenue, **9,064** transactions, **27,358** units sold,
**8.83** average ticket.

## Quick start

1. **Create the database and a dedicated user** (MariaDB `root` usually needs `sudo`):
   ```bash
   sudo mariadb -e "CREATE DATABASE IF NOT EXISTS cafe_sales CHARACTER SET utf8mb4;
   CREATE USER IF NOT EXISTS 'etl_cafe'@'localhost' IDENTIFIED BY 'YOUR_PASSWORD';
   GRANT ALL PRIVILEGES ON cafe_sales.* TO 'etl_cafe'@'localhost';"
   ```
2. **Create `.env` in the repo root.** Every language reads this same file:
   ```
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=etl_cafe
   DB_PASSWORD=YOUR_PASSWORD
   DB_NAME=cafe_sales
   ```
3. **Clean and load the data** (Python, see [python/README.md](python/README.md)):
   ```bash
   cd python
   uv sync
   uv run python limpieza.py
   uv run python carga.py
   ```
4. **Start any API** and open it in the browser:

   | Language | Command | URL |
   |----------|---------|-----|
   | Python | `cd python && uv run uvicorn api:app --reload` | <http://127.0.0.1:8000/docs> |
   | Node | `cd node && npm install && npm start` | <http://127.0.0.1:3000/summary> |
   | Go | `cd go && go run .` | <http://127.0.0.1:8080/summary> |

## Dataset

[Cafe Sales – Dirty Data for Cleaning Training](https://www.kaggle.com/datasets/ahmedmohamed2003/cafe-sales-dirty-data-for-cleaning-training)
(Kaggle), used as-is: 10,000 transactions, 8 columns. Errors come as `ERROR`,
`UNKNOWN` or empty cells in every column. After cleaning, **9,064** rows remain with
no empty cells; values are rebuilt deterministically, never invented. Rules and
numbers: [python/README.md](python/README.md#cleaning--limpiezapy).

## Database

`sql/schema.sql` defines a normalized schema: lookup tables hold each value once and
`sales` references them by foreign key.

```
items (item_id PK, name, menu_price)              ┐
payment_methods (payment_method_id PK, name)      ├──< sales (transaction_id PK, transaction_date,
locations (location_id PK, name)                  ┘            item_id FK, quantity, price_per_unit,
                                                               total_spent, payment_method_id FK, location_id FK)
```

`CHECK (> 0)` constraints on quantity and amounts, and an index on `transaction_date`.

## API contract

Every implementation exposes the same read-only endpoints. Data enters only through
the pipeline, so there are no `POST`/`PUT`/`DELETE` endpoints (smaller attack surface).

| Endpoint | Returns |
|----------|---------|
| `GET /sales` | Sales list. Filters: `date_from`, `date_to`, `item`, `payment_method`, `location`, `limit` (1–10,000, default 100), `offset` |
| `GET /sales/{transaction_id}` | One sale, or `404` |
| `GET /summary` | KPIs + totals by item, payment method, location and month. Optional `date_from`, `date_to` |

| Status | When |
|--------|------|
| `200` | OK |
| `404` | Sale not found |
| `422` | Invalid parameter (e.g. `limit=0`, `date_from=yesterday`, `date_from` after `date_to`) |
| `503` | Database unavailable |

The Python API also publishes the contract as OpenAPI at `/openapi.json`
(interactive docs at `/docs`).

### Contract test

`python/tests/test_contract.py` uses the Python API as the reference and sends the
same requests to the Node and Go APIs, asserting the **same status code and the same
JSON body** (for invalid-parameter `422`s only the status is compared, because
FastAPI uses its own error body format). Last run: **34/34 passed**.

```bash
(cd python && uv run uvicorn api:app --port 8000)   # terminal 1 (reference)
(cd node && npm start)                               # terminal 2
(cd go && go run .)                                  # terminal 3
cd python && PY_API_URL=http://127.0.0.1:8000 NODE_API_URL=http://127.0.0.1:3000 \
  GO_API_URL=http://127.0.0.1:8080 uv run pytest tests/test_contract.py
```

Implementations without a URL are skipped, so the normal test run needs no servers.

> This is a **polyglot** architecture, not horizontal scaling. Horizontal scaling
> means several copies of the **same** service behind a load balancer.

## Power BI dashboard

`powerbi/etl-cafe.pbix` consumes the API over HTTP: an `ApiUrl` parameter, one Power Query
query on `GET /sales?limit=10000`, a `Calendar` date table, seven DAX measures and 11
visuals (KPI cards, pie, line, bar, table, month-over-month combo, treemap, weekday columns).
Because Power BI Desktop is Windows-only, the API is reached through a free Cloudflare
Quick Tunnel.

Step-by-step guide, from installing Power BI to troubleshooting:
[powerbi/README.md](powerbi/README.md).
